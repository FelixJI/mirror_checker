# H03 诊断 APK 操作指南

> 适用：PR-03 交付的诊断应用（`android/app`）。对应实施方案 §10.3 PR-03 与
> §11 H03 的前半部分：实机安装、能力探测、试开相机流与诊断图案观察。
> 完整诊断采集 ZIP 属于 PR-04，本指南不涉及。
> 本应用只做诊断，不输出任何镜面定量结论。

## 1. 准备

1. 从 GitHub Actions 的 `Android (tests + diagnostic APK)` 任务下载 artifact
   `mirror-diag-debug-apk`，解压得到 `app-debug.apk`。
2. 在平板上允许「安装未知来源应用」，安装该 APK（应用名：镜面检测诊断）。
3. 记录平板型号、系统版本（设置 → 关于）、本次测试日期与操作者。

## 2. 能力探测（人工证据：能力报告 JSON）

1. 打开应用 → 「授予相机权限」→「读取相机能力」。
2. 截图保存逐相机列表（含前摄/后摄、硬件能力档、YUV 尺寸数量）。
3. 对每个候选**前摄**点「试开相机流」；后摄也做一次作为对照。
   - 记录每个相机试开后的「实测档位」（manual/lockable/uncontrolled）与原因行；
   - 若显示试开失败，保留失败信息截图，这也是有效证据。
4. 点「生成并分享能力报告」，把 JSON 与同名 `.sha256` 保存到电脑
   （微信/邮件/网盘均可）。两个文件一起提交给软件实施者。

注意：实测档位由「本相机」的能力与试开结果决定；后摄为 manual 不代表前摄可用，
报告内逐相机分列，不允许互相推断。

## 3. 诊断图案观察（人工证据：照片）

1. 应用 → 「诊断图案」。
2. 依次全屏显示内置图案：`diag_black`、`diag_white`、`diag_gray8`、
   `diag_fringe_h8`（竖直条纹）、`diag_fringe_v8`（水平条纹）；
   条纹周期数可用滑杆在 1–16 间调整。
3. 在候选工作距离（起始 0.4–0.8 m，实施方案 §4.2）用另一台相机对着屏幕拍照：
   - 每个图案至少一张正对照片；
   - 条纹图案重点记录：边缘是否整齐（混帧/刷新伪影）、摩尔纹、离焦程度；
   - 灰阶图案记录：各档灰带是否可分辨、有无偏色或闪烁（PWM）。
4. 遮挡检查：确认屏幕开孔/圆角是否落在图案区内，记录位置。
5. 旋转/窗口测试：全屏图案下旋转平板 → 点按退出 → 再次全屏。
   预期：每次按当前 Surface 尺寸重新渲染，系统栏隐藏；若出现拉伸、
   错位或残留旧图案，截图记录（属于缺陷证据）。

## 4. 照片与报告的命名

- 照片：`H03_<设备型号>_<图案ID>_<距离cm>_<序号>.jpg`
  （例：`H03_TestPad_diag_fringe_h8_60cm_01.jpg`）。
- 报告：保留应用生成的文件名（含 UTC 时间戳），不要手工编辑 JSON 内容；
  如需备注，另建文本说明。

## 5. 提交与判定

把能力报告（JSON + sha256）、探测截图与图案照片交给软件实施者，
用于确定 PR-04/PR-06 的优先相机与流配置。是否进入定量支持名单，
以 G0/G1 门槛为准（实施方案 §12）；本指南的任何结果都不单独构成
精度证明。
